# Web3 交易所功能开发路线图

> 作者：项目经理（PM）· 基于主流交易所（Binance/OKX/Bybit）功能体系差距分析
> 原则：务实分阶段，优先"高频核心 + Web3 差异化"，兼顾单人可落地、低成本

## 二、差距分析（对比主流交易所）

### 核心缺失
- **实时推送**：当前 3s 轮询，主流为 WebSocket 实时行情/盘口/成交/深度
- **进阶订单类型**：仅限价/市价；缺 Stop-Limit/OCO/Trailing/Post-Only/IOC/FOK
- **资产划转**：缺 现货↔账户 划转、资金明细全量分页
- **交易品种**：仅现货；缺 合约/杠杆/期权

### 资产/理财缺失
- Staking/Earn 理财、法币通道(P2P)、定投

### Web3 定位缺失（本项目的差异化关键）
- **Web3 钱包**（托管/自托管、助记词、链上资产）
- 跨链/DEX 聚合/NFT

### 安全/合规缺失
- 风控引擎（异常/限额）、交易 API 密钥管理、设备管理/反钓鱼码

### 生态/运营缺失
- 推荐返佣、公告/帮助中心/客服、市场深度图、手续费等级、多语言

## 三、分阶段路线图

### Phase 1 —— 现货核心补全（P0，价值高/成本中，2-4 周）
1. **WebSocket 实时行情推送**（ticker/盘口/最近成交/K线增量）——消除轮询，交易体验质变，主流标配
2. **进阶订单类型**：Stop-Limit(止盈止损) → OCO → Post-Only/IOC/FOK → Trailing
   - 依赖：order 域加"条件单"存储 + 行情触发任务（触发价达成交价即转普通单）
3. **资产划转 + 资金明细全量**：现货账户间划转；按用户分页拉全部流水/成交
4. **我的挂单/历史订单页**：按用户状态过滤（当前仅按 orderNo 查）

### Phase 2 —— 交易扩展 + 资产增值（P1，价值高/成本高，4-8 周）
5. **杠杆现货（Margin）**：借币/抵押/平仓（资产 + 风控）
6. **Staking/Earn 理财**：活期/锁仓质押、收益结算（asset + 定时任务）
7. **Web3 钱包**（差异化核心）：托管钱包(私钥分片加密存储) / 自托管(助记词导入) / 链上资产展示
8. **风控引擎**：限价异常、频率限制、地址白名单、提现二次验证

### Phase 3 —— 生态与合规（P2，4-8 周）
9. **合约/永续**（最重）：资金费率、标记价格、杠杆/强平/风险限额、多空持仓——交易所收入核心
10. **推荐返佣**：邀请链接、层级佣金结算
11. **公告/帮助中心/客服工单**：内容运营
12. **市场深度图(Depth Chart)** + K线更多指标(成交量分布/资金流向)
13. **多语言(i18n) + 多币种法币**
14. **交易 API 密钥管理**（用户级，OpenAPI）

## 四、建议与取舍
- **先做 Phase 1**：WebSocket + 进阶订单 + 划转——补齐现货交易的专业性，成本可控、见效快。
- **Web3 钱包应提前**（Phase 2 首位）：这是"Web3 交易所"区别于普通 CEX 的差异化亮点，价值大于合约。
- 合约/永续是**最大工程**（撮合/风控/资金费复杂），建议放在路线图后端，作为长期目标。
- 每项遵循：先契约文档 → 角色子代理并行(后端/前端) → 统一编译/运行/联调 → git 提交。
